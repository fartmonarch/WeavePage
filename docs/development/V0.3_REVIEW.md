## 3. 已解决的问题：响应只剩 request_id

现象：`POST /api/generate` 返回 200，但响应体只有 `request_id`；前端显示“暂无代码”。

原因：响应类当时继承 `BaseModel`，只声明了 `request_id`。构造响应时传入的其他生成字段被 Pydantic 默认的额外字段处理忽略，未出现在最终响应中。

修复后的结构：

```python
class GenerateResponse(GeneratedComponent):
    request_id: str
```

子类继承父类的 `component_name`、`summary`、`code`、`css`、`preview_code`，再新增 `request_id`。只在类体中写一行，不代表最终响应只有一个字段。

## 4. 已知限制与待优化项

- 当前固定为 React + TypeScript + 普通 CSS；生成组件仅允许 React 依赖。
- 源码视图为只读，未提供编辑后重新预览、ZIP 导出或版本保存。
- 导入范围和 CSS 作用范围主要由提示词约束，尚无完整的静态强制检查。
- 工作台构建检查的是工作台源码，不会对接口返回的源码字符串执行完整类型与行为检查。
- Sandpack 的隔离和资源限制应按实际验证证据描述，不宣称已经具备生产级安全沙箱。
- 前后端长度限制存在差异：后端 CSS 为 12,000 字符、使用示例为 10,000 字符；当前前端分别为 20,000 和 15,000。接口实际仍受后端较小上限约束，后续应统一。这次仅记录差异，保留现有实现。
- 本地 bundler 的具体部署与启动命令尚未进入仓库文档，干净环境复现预览仍需要补齐这部分说明。
